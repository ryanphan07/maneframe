# Maneframe: current state (2026-11-05; v0.2.0 tagged 2026-11-04, later work listed under Unreleased in CHANGELOG.md)

What exists today. Verified means checked by a test or by a run; untested means written but never exercised. Next work: `docs/TASKS.md`.

## Flow

```
upload -> check name and size, save -> job created -> background pipeline:
  extracting   convert if needed (Converting video), corruption and length checks, duration, motion crop box (once per video, 30 frames read in one forward pass)
  analyzing    per 10 s window: sample frames -> vision LLM -> quips (sequential)
  synthesizing finalize timeline -> edge-tts per quip (bounded concurrency) -> measure durations -> schedule
  completed    GET /api/jobs/{id} returns quips + audio_available
```
The browser plays the file as a blob URL (the original, not the transcoded copy). If the browser cannot decode it, the player switches to `GET /api/jobs/{id}/video`, the server's prepared H.264 copy (Range supported; untested in a real browser with an HEVC clip). Upload paths are never served; exports only through the export route.

### Behavior worth knowing
- Limits: extensions `.mp4 .mov .avi`, `MAX_UPLOAD_MB` (2048), `MAX_VIDEO_SECONDS` (1800). Long clips (10+ min) are allowed by the limits but untested. Rejections are HTTP 400 `{"detail": ...}` and delete the file.
- A window that fails (transport error or timeout after one more attempt, unusable JSON after one retry, no frames) is skipped and logged (DECISIONS D4, option B). `CommentaryResponse` has `skipped` (`[{start, end}]`) and `total_windows`; the completed message adds ", skipped n of m parts" and the player lists the ranges. The job fails instead of skipping when the model server is unreachable (no retry), when more than half the windows are skipped, or when 3 in a row are (D4 limits; error is the last failure's category). A job with zero usable quips fails. The job error text is one of: model not reachable or timed out, model returned unusable output, video could not be processed, or the generic "Commentary generation failed" (`pipeline.friendly_error`).
- TTS failures never fail the job: the quip is kept with `audio_url: null, duration_sec: null`; if no clip has audio the job message is "Commentary ready (audio unavailable)".
- `schedule_quips`: audio quips are processed in time order and may not start before the previous audio ends + 0.3 s; shift up to `MAX_SHIFT_SEC` (2.0) else drop (also dropped if the shifted start is past the video end, and the dropped quip's mp3 is deleted); no-audio quips never block. Every shift/drop is logged.
- Cleanup: failure deletes video, frames and audio for the job; success keeps the source video, audio and exports until the job expires (the video is needed for export); `pipeline.purge_expired_jobs` (cleanup loop and every upload) removes expired jobs and their files; startup sweeps `uploads/videos`, `uploads/audio` and `uploads/exports` (the store is empty then).
- One job at a time: an upload while another job is running gets HTTP 409 (no queue). A job with no progress update for `JOB_STALE_SECONDS` (1800) is failed so it cannot block uploads forever.

## Frontend (`frontend/src/`)
- `App.jsx`: upload via axios, then `WS /ws/analyze/{job_id}` with capped exponential reconnect (5 tries), then a 5 s polling fallback on `GET /api/jobs/{id}` (browser-tested 2026-11-06), switches on `msg.status` only, on `completed` fetches `GET /api/jobs/{id}`, shows toast + inline error, `VITE_API_BASE` (default http://localhost:8000).
- `components/VideoPlayer.jsx`: blob-URL video, quip queue driven by `timeupdate`, one clip at a time, video ducked to 0.3 while a clip plays, stale lines (older than 4 s) skipped, seek resets, pause/resume handled, autoplay-block notice, "audio unavailable" notice, clickable commentary list that seeks.
- Completed jobs show `components/ExportControls.jsx`: "Download video", a captions checkbox (default on), a size choice (Original / Vertical 9:16), optional Start/End seconds with "Set start" / "Set end" buttons that read the player position, a "Rendering video…" state and an error toast; the file is saved as `maneframe_<original name>[_9x16][_<start>-<end>s].mp4` (`exportOptions.js` builds the request params and the name). The response is held in browser memory as a blob. Browser-tested 2026-11-06 (not the audio ducking).
- A style dropdown (Hype, Deadpan, Broadcast; hardcoded list that must match `prompts/styles/`) sits next to the file picker and is sent as the `style` form field. Browser-tested 2026-11-06.
- `components/LabelPanel.jsx` (under the commentary once completed): "Add label at current time" pauses the video and opens a form (label, quality, note); the list seeks on click, has Delete and a "Download CSV" link. Lint and build pass; browser-tested 2026-11-06.

- `backend/requirements.txt` is pinned (includes `websockets`, required by uvicorn for the WS route); `backend/requirements-dev.txt` adds pytest.

The launcher picks free ports (8080/8000 preferred), starts llama-server and the backend with settings as environment variables, and stops both on close or Ctrl+C (Windows job object). Data is in %LOCALAPPDATA%\Maneframe or MANEFRAME_DATA_DIR. On first run (or when `config.json` has no valid choice) it prints RAM, GPU (from `llama-server --list-devices`, an integrated GPU reports shared memory) and free disk, recommends the 35B at 15 GB of RAM or more, else the 9B; GPU memory is shown, not used, and downloads the chosen model from Hugging Face (`packaging/models.json`: pinned revisions, sizes, sha256) with progress, Range resume, 3 retries and a sha256 check; files already present are hashed once and recorded in `<data>\config.json`; Change model.bat clears the choice. Launcher tests: backend/tests/test_launcher.py. Tested on this PC with a reduced PATH; double-click in Explorer and a machine without the VC++ runtime are untested (MC-8).
- llama-server at 127.0.0.1:8080 with `--mmproj`. Qwen3.5-9B Q4_K_M for development, Qwen3.6-35B-A3B for real runs (timings in docs/BENCHMARKS.md).
- edge-tts must be >= 7.3.1 (7.2.8 gets 403).

## Known gaps for long clips
The pipeline handles long clips by limits only; the 327 s hoco2026 clip (1080p copy) ran end to end on the 35B in 23.3 min with no skipped windows (docs/BENCHMARKS.md, 2026-11-05). Finished quips appear while the job runs (`result.partial`); verified live 2026-11-02: first partial quip with audio at 70.5 s of 221.5 s, none vanished from the final result. A page refresh resumes the job: the job id, filename and style are kept in localStorage (`maneframe.job`), `App.jsx` reloads it with GET /api/jobs/{id}, reconnects the WebSocket if it is running and plays GET /api/jobs/{id}/video; a 404 clears it with a notice. Verified by Vitest and by the Playwright browser check (2026-11-05). Skipped-window handling and the HTTP 400 fallback are covered by tests only, not run against a live server. Not hardened for restarts: the job store is in memory.
